# UI Polish 通用走查清单

> 对标 Apple / Linear / Vercel 级细节质量。每条标注验证方式：**[眼]** 截图目测 / **[测]** 读计算样式或 DOM / **[动]** 交互后观察。
>
> 项目探测到的 token 与规范永远优先于下面的通用数值。数值是项目未定义时的兜底标准。

## 1. 排版 Typography

- [ ] 字阶克制：全站字号层级 ≤7 级，级间比例协调（常用 1.2–1.33 倍率）。[测]
- [ ] 字重层级：标题/标签/正文分工明确，不滥用 700；大标题可用 600–650。[测]
- [ ] 行高：正文 1.5–1.7；标题收紧到 1.1–1.3；长文段落不留在浏览器默认值。[测]
- [ ] 字距：大标题（32px+）有轻微负字距（约 -0.02em）；正文不动。[测]
- [ ] 长文行宽有上限（约 65–75ch）；超宽屏下文本不拉满。[测]
- [ ] 中英文混排：数字、英文与中文之间空隙自然；标点不悬挂错位。[眼]
- [ ] 数字（计数器、金额、时间戳）用 tabular-nums，排版不跳动。[测]
- [ ] 截断策略：超长文本按设计省略或换行，绝不溢出容器。[眼]
- [ ] 无远程字体导致的 FOUT/布局抖动；若项目禁止远程字体，确认无请求发出。[测]

## 2. 间距与网格 Spacing

- [ ] 所有 margin/padding 落在项目间距 token 上（常见 4px 基：4/8/12/16/24/32/48）；无 13px、17px 这类一次性值。[测]
- [ ] 同级列表/卡片间距完全一致；相关元素间距 < 不相关元素间距（接近性原则）。[眼]
- [ ] 组件内 padding 有设计意图：文本块通常上下略小于左右，或按 token 成组。[眼]
- [ ] 页面级留白节奏一致：区块间呼吸感均匀，无突然挤/突然空。[眼]
- [ ] 边缘对齐：标题左缘、按钮右缘、跨区块内容边界在同一轴线上。[眼]

## 3. 色彩与对比 Color & Contrast

- [ ] 正文/背景对比度 ≥ 4.5:1；次级文字 ≥ 4.5:1（大字 ≥ 3:1）。[测]
- [ ] 强调色克制：一屏内主强调色出现次数可数；语义色（红=错误、绿=成功）不挪作装饰。[眼]
- [ ] 状态不只用颜色传达：同时有形状/图标/文字变化。[眼]
- [ ] 每个主题（亮/暗/其他）独立过一遍本清单；切换主题无闪烁、无未适配的硬编码色。[眼][动]
- [ ] 边框/分割线亮度有层次，存在但不刺眼。[眼]

## 4. 交互与可达性 Interaction & A11y

- [ ] 所有可点目标 ≥ 44×44px（含纯图标按钮）；视觉尺寸必须小时用透明扩展点击区。[测]
- [ ] Tab 顺序与视觉顺序一致；无 focus 丢失、modal 外无 focus 陷阱。[动]
- [ ] focus ring 清晰可见且符合设计语言（不是裸奔的浏览器默认框，也不是 outline: none 无替代）。[眼][动]
- [ ] hover 反馈明确但安静：背景/边框/亮度的微变化，而不是位移或大阴影。[动]
- [ ] 按下态存在（如 scale ~0.97 或亮度下沉）。[动]
- [ ] 禁用态保持可读，不是单纯降到看不清的透明度。[眼]
- [ ] 图片/图标有 alt 或 aria-label；纯装饰元素 aria-hidden。[测]
- [ ] 触控：功能不依赖 hover 才能发现；无 300ms 点击延迟。[动]

## 5. 动效 Motion

- [ ] 时长：微交互 150–250ms；面板/页面级 250–400ms；无 >500ms 的拖沓。[测]
- [ ] 缓动：入场/出场用 ease-out 系（如 cubic-bezier(0.16,1,0.3,1)）；无 bounce、无 linear。[测]
- [ ] 无 `transition: all`——过渡属性显式列出。[测]
- [ ] 不动画布局属性（width/height/top/left）；用 transform/opacity。[测]
- [ ] `prefers-reduced-motion` 下降级或跳过动画，最终状态保持一致。[测]
- [ ] 页面隐藏时（document.hidden）暂停非必要循环动画。[测]
- [ ] 滚动触发的动效不阻塞滚动、不抖动。[动]

## 6. 组件状态 States

- [ ] 加载态：skeleton 或 spinner，不是空白/闪烁；>300ms 才出现避免闪烁。[动]
- [ ] 空态：有插画或说明 + 明确的下一步操作，不是裸"暂无数据"。[眼]
- [ ] 错误态：文案说人话并给出补救动作；表单错误定位到字段。[眼][动]
- [ ] 成功态：操作有确认反馈（toast 或状态变更）。[动]
- [ ] 极端内容：超长标题、零条数据、一百条数据下布局都不塌。[眼][测]

## 7. 响应式 Responsive

- [ ] 所有探测到的测试断点都走查（兜底：375 / 768 / 1024 / 1440px）；任何视口无横向滚动条。[眼][测]
- [ ] 断点临界处（如 767px 与 769px）布局不塌、不重叠。[眼]
- [ ] 移动端：导航可达、正文字号 ≥ 14px、行宽舒适。桌面端：内容不超宽失读。[眼]
- [ ] 刘海屏/底部指示条用 `env(safe-area-inset-*)` 处理。[测]
- [ ] 横屏/矮视口（如 812×375）关键操作可达。[眼]

## 8. 质感细节 Fit & Finish

- [ ] 图标来自同一套体系，stroke 粗细一致，视觉尺寸光学对齐（只设相同 px 不够）。[眼]
- [ ] 圆角按层级一致；嵌套容器外圆角 > 内圆角。[眼]
- [ ] 深度遵循项目策略（亮度分层、克制投影等），不用随手加的阴影。[测]
- [ ] 分割线：1px、低对比；能用留白就不用分割线。[眼]
- [ ] 图片/头像：加载失败有兜底；用 `aspect-ratio` 锁比例，不拉伸变形。[眼]
- [ ] 光标：可点元素 pointer、输入框 text、拖拽 grab/grabbing。[动]
- [ ] `::selection` 样式与主题协调。[眼]
- [ ] 滚动条：定制滚动条不喧宾夺主；overflow 只出现在预期位置。[眼]

## 9. 一致性 Consistency

- [ ] 同类组件跨页面表现一致：按钮、输入框、卡片、标签各处同款。[眼]
- [ ] 文案：语气统一、标点统一（全角/半角不混用）、大小写规则统一。[眼]
- [ ] 组件跨主题结构与间距完全一致，只有颜色变。[眼]
